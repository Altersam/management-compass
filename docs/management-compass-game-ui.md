# Management Compass Game UI — проект под давлением

## Аудит до правок

Целевая игра — `game.html`, проект запуска внутреннего сервиса. Прототип `C:\Users\alter\Downloads\pmqwen_improved_v4_multidomain.html` изучен как визуальный/UX ориентир: четыре зоны, компактная рука команды, живой Gantt, решения событий, прогноз и запуск. Его Math.random, формулы и случайные отраслевые проекты не подменяют текущую учебную модель.

Текущая модель: 20 дней, бюджет 1 200 000 ₽, семь задач, пять людей и эксперт. Есть параллельная ветка обучения после прототипа, зависимая интеграция и приёмка, перегрузка/fatigue, delayed rework/adoption/metrics, seeded external plan, causal snapshots и альтернативы после финала. Назначение одного человека на несколько задач уже разрешено.

UX-дефекты: общий header курса и footer, крупный editorial h1, пять HUD-показателей, подсказки/инструкция/cycle до поля; три колонки с командой слева и длинными событиями справа; mobile скрывает поле/команду вкладками; профиль и точное соответствие навыка видны до решения. Обычное время запуска не собрано с прогнозом в едином Action Bar.

## Границы

Сохраняются revision 1, IDs задач/людей, legacy balanceVersion, алгоритмы работы/переделки/применения, сохранённые earned runs, archive/export/import и прежняя simulation. Новый scenarioVersion применяется только новым попыткам страницы игры; старые saves не получают новые случайные события задним числом. Общая оболочка сайта и другие игры не меняются.

Новая presentation: отдельная компактная шапка игры, Goal Bar (цель + день/бюджет/качество), Gantt как поле, Resource Tray справа/горизонтально mobile, Action/Forecast Bar. Зависимости/параллельная ветка показаны на поле. Задача настраивается в drawer; theory только в help/объяснении/финале. Онбординг — выбор человека → назначение → прогноз/запуск. Event dialog содержит trade-offs и альтернативу перераспределения, не оценку человека.

Новое событие-сценарий — data-driven организационный контекст с человеческими случаями; это не обещание многодоменной симуляции. Новый seed может менять допустимые навыки/стоимости/доступность/объёмы, но сохраняет authored causal structure. Replay той же ситуации использует сохранённый scenarioVersion и seed.
