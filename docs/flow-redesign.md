# «Бутылочное горлышко»: физический поток

Изучена модель: четыре станции, ticker 1200 ms, три arrivals за tick, обратный порядок обработки, WIP 4/8/12/20, внешняя очередь, seeded дефекты и возвраты, расходы и конец по бюджету/20 ticks. Формулы сохраняются. Прямые controls используют прежние station/upgrade/wip/check.

Для финала добавляются optional наблюдения flowTrace после обычного tick/upgrade: видимые размеры очередей, выдано, outside, spent и фактическое добавление ресурса. RNG и расчёты не меняются. Legacy save без снимков не получает выдуманных исторических пиков: граница наблюдения явно отмечается.

## Реализация и аудит

`flow-factory.js` — локальный renderer/controller через прежний mountUI. Четыре станции стоят на одной линии, outside физически слева. На mobile линия вертикальна. Все реальные queued IDs показаны жетонами; WIP не удаляет внешние обязательства. Сверху три коротких показателя: выдано/незавершено/расход, интервал вторичен.

Каждый [+] находится на самой станции; controller вызывает прежние station + upgrade и общая оболочка ставит ticker на паузу. Delta показывает фактическую мощность до/после, без обещания ускорить весь поток. При quality OFF мощность соответствующей операции остаётся 20 по старой формуле, а не искусственно растёт от добавления человека. WIP на входе: − / число / + для 4/8/12/20. ON/OFF только на проверке.

Короткая анимация сопоставляет фактические позиции одного request ID между состояниями. При росте returns объект проходит через вход; это учитывает reverse processing, который может за один tick вернуть исправленный запрос снова к проверке. Ошибка видна только у реально выданного defective item, не раскрывает скрытый defect заранее. Reduced-motion отключает движение.

До наблюдения очередь не названа узким местом; нейтральное замечание о неравномерном росте появляется после нескольких интервалов. Финал использует flowTrace: наблюдавшиеся пиковые очереди, интервалы добавления ресурса, done/outside/errors/rework/spent. Peaks — размеры видимых очередей в снимках после tick, не максимумы выдуманных микроопераций внутри tick. Для legacy без flowTrace доступны только конечные итоги и честное указание отсутствующей истории.

Финальный вывод сопоставляет добавленный ресурс и очереди этого run; не заявляет измеренный эффект несыгранной альтернативы. Исходный report API сохранён, новый визуальный разбор не начинает с общего утверждения «ограничивала проверка» независимо от действий игрока.

Проверки итогового набора: **150 Node / 101 browser / 28 a11y**, lint/build/diff успешны. Подтверждены 3 arrivals/tick, reverse processing, сохранность всех обязательств, WIP/outside, capacity, quality returns/errors, budget ending и 20 ticks. Browser проверяет direct +, WIP, ON/OFF и auto pause; axe — очереди и controls в обеих темах. Legacy без trace и unknown fields не теряются при чтении.
