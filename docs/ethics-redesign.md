`evaluate()` проверяет существенный внешний срок и criterion deadline, независимую проверку личного влияния, достаточность раскрытия criterion и открытые rule/deadline. Его формула остаётся прежней. Свободный note не анализируется: ограничение 2000 символов, минимум 10 перед завершением. Прежние завершённые попытки и архивы остаются читаемыми.

## Новый цикл

Досье → факты → решение → защита объективности → объяснение → разбор. Вход содержит одну игровую кнопку. Личная связь открывается источником, а не вводным абзацем. Решения выбираются текстовыми строками; textarea появляется после них. Optional casework хранит только этап интерфейса, активный источник и одну мягкую попытку пересмотра. Legacy defaults выводятся из checks/history/note без сброса данных.

При слабом основании или незащищённой замеченной личной связи предложение пересмотра сохраняет все факты и текст. После одной попытки игрок может явно завершить с выбранным основанием; разбор не подменяет его другим решением.

## Реализовано

- На входе одна игровая кнопка «Открыть заявки». Длинное описание каталога скрыто только на странице ethics, чтобы оно не раскрывало личную связь заранее.
- Досье разделены колонками и линиями. Исходная надёжность команды А и зависимая работа команды Б сохранены; личное знакомство показывается после connection. После deadline срок добавляется в каждое досье согласно variant, без команды выбрать А или Б.
- Факты общего действия находятся в отдельной области открытых источников. Повторный просмотр бесплатен; в досье остаются короткие сведения, полный источник можно перечитать.
- Перед выбором заявки обязательны две проверки. Далее allocation → criterion → influence, если открыт connection → disclosure → note. Четыре select заменены отдельными текстовыми решениями. Неоткрытая connection не меняет influence скрытым автоматическим выбором.
- Optional `casework` хранит stage/activeSource/correction/reconsidered. Legacy defaults читаются из checks/history/note; сам render не перезаписывает старые значения. Phase/revision, начальные значения решений, attempts и unknown fields сохраняются.
- Первый submit слабого основания показывает одну мягкую петлю: вернуться к фактам или изменить основание. Право повторной фиксации появляется после этого сообщения. Обычные возвратные ссылки до feedback его не обходят. При обратном переходе выбранная заявка и текст не стираются.
- Оценка note остаётся только проверкой длины, без анализа содержания. Итоговая attempts содержит фактический результат неизменённой evaluate(), а не подменённый «правильный» ответ.
- Финал начинается с четырёх строк выбранной процедуры и авторского объяснения. Затем перечисляет только открытые факты, непроверенные источники и ограничения основания. Морального рейтинга нет.

Общая оболочка не переписана: ethics использует существующие opt-out/history/practiceCycle/quietStatus/compactTransfer/focus и renderReport. CSS добавлен только с ethics-specific классами. Другие игровые движки и их стили этим этапом не изменялись.

## Self-audit

| Вопрос | Ответ |
|---|---|
| Сколько controls на первом экране | Одна игровая кнопка. Дополнительно остаются ссылка в каталог и общая навигация продукта |
| Остались ли select | В механике ethics — нет. Кнопки отдельно выбирают заявку, критерий, защиту и объём раскрытия |
| Видно ли различие «факт / решение / защита» | Факты на досье и в исследованных источниках; решение — отдельный вопрос о ресурсе и основании; защита — отдельный этап после замеченной личной связи |
| Не раскрывает ли UI ответ заранее | Вход не показывает срок и знакомство. Проверка срока добавляет «сегодня/завтра», но не выбирает заявку. Источники содержат прежние правила и процедурные объяснения; варианты решения не выделяются как правильные, начальные defaults не считаются сделанным игроком выбором |
| Можно ли пересмотреть | Да: открыть оставшийся факт, изменить заявку или основание и снова объяснить решение. После corrective feedback сохраняются checks/budget/note; допускается осознанная фиксация даже неэталонного варианта, с честным разбором |

При неоткрытой connection финал прямо отмечает этот предел: отсутствие проверки не доказывает ни отсутствие связи, ни нарушение. Непроверенный источник не превращается в якобы найденное доказательство. Наличие совпадающих слов в note не меняет оценку модели.
