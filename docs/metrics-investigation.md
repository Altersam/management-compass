## План изменения

Одна цифра → открыть расследование → вопросы → один выбранный факт → контекстное действие → доска коротких найденных фактов → вывод кнопками → следующий факт → авторская формулировка → одна мягкая петля пересмотра → разбор.

Новые optional поля обслуживают только стадии этого интерфейса. Legacy saves читаются с вычисленными defaults; состояние модели и сохранённый текст не сбрасываются. Общая оболочка получает необязательные game-level opt-out history/practiceCycle и hook финального markup; default остальных игр остаётся прежним.

Сильный вывод success/failure сначала получает сообщение о недостаточности доказательства, а не мгновенный финал. После дополнительной проверки или явного пересмотра игрок может подтвердить свою формулировку; история исследования и note сохраняются. Это одно приглашение к проверке границ, не автоматическая оценка свободного текста.

## Реализовано

Стадии хранятся в optional `investigation`: headline/investigate/conclusion/next/write, activeProbe, correction, reconsidered. Поля старой модели и revision 1 сохранены. Отсутствующий объект выводится из уже открытых probes, history и note без перезаписи при чтении. Завершённые старые попытки сразу открывают новый разбор, а не запускаются заново. `samples`, `calculate()`, `fact()` и прежний data-report не изменены.

Вопросы и действия принадлежат metrics.js. Общая ui.js расширена opt-out и hook без изменения default остальных игр. История остаётся в сохранении, но отдельного блока history и practice cycle у metrics нет. Live status сохраняется для screen reader без постоянного пустого места. В финале общий перенос рабочего действия свёрнут; ссылки, профиль и isolated restart/archive сохранены.

На телефоне после проверки фокус переходит к открытому факту. «Выбрать другую проверку» возвращает к вопросам; при corrective feedback фокус переходит к самому сообщению. Исходные значения success/charts не выделяются как уже выбранные ответы до реального действия игрока.

| 4. Остались ли select | В игре — нет. Вывод и следующий факт выбираются строками-кнопками; общий выбор оформления/профиля относится к оболочке |
| 5. После первой проверки | Бюджет уменьшается на один, появляется выбранный факт и одна строка «Что уже известно». Повторное чтение бесплатно |
| 6. Видно ли 60 ≠ 100 | После denominator — полоса 60/40, текстовые подписи и явное 60 ≠ 100; доступно без различения цвета |
| 7. Как обнаруживается сильный вывод | Inline «Вывод сильнее имеющихся данных» с уточнением границы среднего. Ни «неправильно», ни оценки личности нет |
| 8. Можно ли исправить | Можно открыть дополнительный факт или пересмотреть вывод после исчерпания бюджета. Уже открытое, бюджет и текст не сбрасываются. После одного приглашения допустимо осознанно подтвердить свой вариант; свободный текст не анализируется автоматически |
| 9. Какие данные скрыты | Другие каналы, ожидание, повторы, состав расчёта и распределение раскрываются вопросами. Полная причинная цепочка появляется только после завершения |
| 10. Где ещё форма | Единственное авторское textarea после выбора вывода и следующего факта. В завершённом разборе отдельно свёрнута прежняя форма переноса действия в работу; restart содержит прежнее поле сценария |

Любые две разные проверки позволяют перейти к формулировке, включая period + distribution. Предпочтительный hypothesis/users остаётся эталоном объяснения, а не обязательным набором открытых probes. Проверка периода — полезный отрицательный результат; она не обязана раскрывать новый дефект.
