# «Совещание без решения»: встреча вокруг выбора

## Исходная модель — до правок

11 октября 2026. Полностью прочитан meeting.js и существующий engine/browser path. Пять участников it/finance/ops/legal/owner, четыре вопроса fact/constraint/authority/option. Новый вопрос стоит 4 минуты, повтор не расходует время и не добавляет вторую реплику. Лимит 30; фиксация занимает ещё 3 минуты с cap 30.

Два seed-сценария: urgent — окно IT 2 дня, бюджет 24, дата 7; flexible — окно 6, бюджет 35, дата 12. Пилот: 18/2, полный выпуск: 30/5, полный объём позже: 24/10. Для исполнимости нужны пять подтверждений: it:constraint, finance:constraint, ops:fact, legal:constraint, owner:authority; право общего ресурсного выбора у owner. evaluate/create/act/answer/validate/report не меняются.

Commit сохраняет result в attempts. Исполнимый выбор, вторая попытка или предел времени завершают встречу. После первой слабой попытки, если осталось время, новый интерфейс предлагает вернуться к разговору. Это отображение существующей модели двух attempts, без третьей попытки или нового бюджета.

## Композиция

Пять разных interest вокруг условного стола, активный человек и последняя адресованная реплика. Большой остаток времени — единственная основная метрика. Четыре естественных вопроса при выбранном человеке. Разговор свёрнут; маркеры на местах показывают реально заданные вопросы. Полоса решения доступна постоянно; план выбирается строками, owner — на самом столе в режиме ресурсного выбора. UI selection/reply/gap-dismissed — локальные состояния, model поля и revision 1 остаются прежними.

## Реализовано

`meeting-room.js` содержит локальный renderer/controller этой встречи через существующий mountUI hook. Общая оболочка не изменяется. На широком desktop вопросы находятся рядом со столом в отдельной узкой колонке; активный участник выделен. После ответа появляется только его актуальная реплика. На mobile участники располагаются в компактной сетке, реплика — непосредственно у человека, вопросы ниже. Ни один ответ не требует hover.

Каждое место содержит исходный interest, а не заранее раскрытый правильный выбор. Различия места/линий дополняют функцию: IT — обещанное внедрение, Финансы — ресурс, Операции — исключения, Юрист — обязательная проверка, Владелец — полезный выпуск. Маркеры «Факт найден / Ограничение известно / Право уточнено / Вариант предложен» появляются только по known.

Transcript свёрнут под «Разговор · N реплик». Повтор вопроса показывает прежний ответ, не дублируя messages и не увеличивая minutes. План всегда доступен, выбор owner производится кликом/Enter по самому участнику после «Кто принимает ресурсный выбор?». При новом выборе владельца до первого явного назначения никто не выделяется как уже выбранный; прежний model default it не переименован и не мигрирован. Старые явно выбранные owner/plan восстанавливаются.

После первой неисполняемой фиксации показываются максимум два главных разрыва: право владельца, окно IT/стоимость или непроверенные условия. «Вернуться к разговору» сохраняет messages/known/attempts и выбранный план. Пересмотр не создаёт третью попытку и не продлевает время: при второй фиксации или 30 мин. встреча завершается по старой engine-логике.

Финал: выделенное время → стол с реально выбранным владельцем и маркерами → заданные вопросы/ответы → действительно подтверждённые существенные условия → plan/owner → исполнимость. Сохранённые две attempts можно раскрыть отдельно. Четырёх KPI-карточек нет. Для старой истории без timestamps не выдумываются минуты каждой реплики; показываются реальные s.minutes и сохранённый порядок messages.

## Self-audit

- Основной объект — пять участников и общий вопрос в центре. Один крупный timer, без параллельного dashboard.
- Четыре вопроса звучат естественно; внутренние fact/constraint/authority/option в UI не показываются.
- Одновременно видна одна актуальная реплика; полный разговор открывается по запросу.
- Plan и owner не являются select. Выбор владельца идёт через того же человека за столом; keyboard-фокус переводится к вопросу/реплике/решению. Escape отменяет режим назначения.
- Полоса решения доступна независимо от числа исследованных условий. Она не обещает исполнимости до проверки.
- Первый gap — процедурные ограничения, без оценки личности. Возврат не стирает разговор.
- Единственные формы в итогах — свёрнутый перенос рабочего действия и прежнее поле сценария рестарта. В самой механике формы нет.
- Engine create/act/validate/answer/evaluate/report и revision 1 сохранены; frontend selection/reply не добавляют поля в persisted model.
