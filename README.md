# Management Compass — практика административной работы

Локальный интерактивный справочник: **что делать в конкретной ситуации, почему это помогает и как проверить результат**.

Целевой репозиторий: [Altersam/management-compass](https://github.com/Altersam/management-compass).

## Что внутри

- 10 обезличенных разделов административной практики с 30 теоретическими объяснениями.
- 20 техник: когда применять, почему работают, 5 шагов, пример, типичная ошибка, проверка пользы и собственный рабочий шаблон.
- 8 маршрутов по симптомам: перегрузка, срывы сроков, конфликт, очередь заявок, непринятое изменение, сомнительные показатели, документы, справедливость.
- 10 кейсов-самопроверок с разбором **каждого** варианта и вопросом к собственной практике.
- 3 самостоятельные страницы по Адизесу: PAEI, CAPI, жизненный цикл. Авторские интерактивы для рефлексии, не официальные диагностические тесты.
- Рабочие конструкторы поручения и сложного разговора, калькулятор мощности этапа.
- Личные локальные профили, избранное, черновики, ответы, наблюдения по моделям и редактируемый дневник.
- Поиск по разделам и дневнику, фильтр записей, рефлексия недели, экспорт/импорт данных и печать.
- FAQ и список теоретических оснований.

Справочник открывается по необходимости. Здесь нет обязательного прохождения, оценок сотрудников, учебных назначений, сертификатов или серверных аккаунтов. Все ситуации обобщены; исходные документы и презентации не входят в публикацию.

## Локальный запуск

Требуется Node.js 20 или новее. Установка пакетов для обычного использования **не нужна**.

```sh
npm start
```

Откроется `http://127.0.0.1:4173`. Терминал должен оставаться открытым; `Ctrl+C` завершает локальный сервер. Он выдаёт только статические страницы и не принимает/хранит ваши данные.

Другой порт, без автоматического открытия браузера:

```sh
node scripts/serve.cjs --port 4174
```

`index.html` можно открыть напрямую для чтения, однако браузеры по-разному разделяют хранилища `file://`. **Для общего профиля и дневника на всех страницах используйте один локальный HTTP-адрес.** Не переключайтесь между `localhost` и `127.0.0.1`: это разные хранилища браузера.

После запуска интернет не требуется: нет CDN, внешних шрифтов, аналитики или API. Внешние ссылки есть только на странице литературы и открываются по вашему выбору.

## Где находятся мои данные

Все записи сохраняются в `localStorage` браузера под ключом `management-compass:v1`. Каждый профиль содержит отдельные данные: дневник, избранное, рабочие черновики, выбранные ответы и параметры рефлексии. Открытая страница привязана к профилю через `?user=…`; другая вкладка может работать с другим профилем.

Это разделение записей, не вход с паролем: человек с доступом к тому же браузеру может выбрать любой локальный профиль. Серверу и GitHub личные записи не отправляются.

**Экспорт данных** создаёт JSON резервной копии всего текущего профиля, включая рабочие шаблоны и параметры Адизеса. **Импорт** создаёт новый профиль, сохраняя существующие. Отдельный экспорт дневника можно импортировать в выбранный профиль; записи с теми же идентификаторами не дублируются.

Экспортируйте данные перед очисткой браузера, переносом на другое устройство или сменой адреса сайта. Если браузер запрещает сохранение, приложение сообщает об этом; записи текущей страницы остаются доступны для экспорта до её закрытия.

## GitHub Pages

1. Разместить содержимое этой папки в корне `Altersam/management-compass` на ветке `main`.
2. В **Settings → Pages → Build and deployment** выбрать **GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` проверяет структуру и сценарии браузера, затем публикует только HTML/CSS/JS из `site/`.

Ожидаемый адрес при включённых Pages: `https://altersam.github.io/management-compass/`.

GitHub Pages — статическая публикация того же справочника. Личные данные остаются локальными. Локальный адрес и адрес Pages имеют разные хранилища; для переноса используйте экспорт/импорт. Подготовка workflow сама по себе не публикует репозиторий.

## Проверки и развитие

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

`npm test`: разделение профилей, перенос данных, устойчивость при недоступном хранилище, целостность контента и ссылок, отсутствие исходных документов в публичных файлах. Браузерные проверки: страницы, рабочие шаблоны, дневник, кейсы, импорт и мобильная вёрстка.

### Структура

```text
index.html                    Главная рабочая страница
navigator.html                Ситуация → маршрут решения
modules/module-01…10.html     Страницы разделов
adizes*.html                  Отдельные страницы по Адизесу
sources.html                  Теоретические основания и литература
assets/content.js             Объяснения, техники, маршруты, кейсы
assets/store.js               Версия данных, профили, валидация импорта
assets/app.js                 Главная страница и дневник
assets/chapter.js             Техники, рабочие формы, калькулятор
assets/cases.js               Общий разбор кейсов и сохранение рефлексии
assets/adizes.js              Интерактивы дополнительных моделей
assets/page.js                Общая навигация справочных страниц
assets/styles.css             Адаптивная локальная вёрстка
scripts/                      Сервер чтения и сборка статического сайта
tests/                        Автоматические проверки
```

Чтобы добавить технику, редактируйте данные в `assets/content.js`; общая страница автоматически создаст пошаговое описание и рабочую форму. Кейс содержит ситуацию, варианты, наиболее обоснованный выбор при заданных условиях, последствия всех вариантов и вопрос для рефлексии.

## Содержание и применимость

Справочник использует модели PDCA, SMART, SBI, RACI, SIPOC, Lean, ADKAR и идеи Адизеса в авторском обобщённом изложении. Список книг и границы интерпретаций — в `sources.html`. Рабочие формы не воспроизводят официальные тесты и не определяют стадию организации по двум шкалам.

Конкретные полномочия, обязательные формы и правила исполнения определяются вашей организацией. Важен проверяемый эффект выбранного действия, а не количество заполненных форм.
