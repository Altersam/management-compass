## Проект под давлением

[Начать игру →](game.html)

Запустите внутренний сервис заявок за 20 рабочих дней с бюджетом **1 200 000 ₽**. Вы назначаете людей, наблюдаете план проекта и меняете условия работы, пока время движется. Первое прохождение рассчитано на 10–20 минут с паузами; есть ускорение времени.

- Семь связанных задач на Gantt: требования, прототип, проверка, интеграция, согласование, обучение и запуск.
- Пять сотрудников с разными навыками и наблюдаемым способом работы; дополнительный эксперт стоит дороже.
- Одновременные задачи создают переключения и усталость; поздняя проверка может вернуть готовую работу.
- Внешние события и последствия ваших решений: требования подразделений, отсутствие коллеги, доступ IT, перегрузка, ручная очередь, обходы и метрики.
- Финал показывает срок, расходы, переделку, перегрузку, использование и ручные решения — с выводами о конкретном прохождении.

Можно поставить время на паузу, открыть короткое объяснение события и вернуться к тому же проекту. При возвращении игра предлагает продолжить. На телефоне — вкладки «Проект / Команда / События». Старый формат [истории сервиса](index.html#final) тоже доступен.

## Курс и рабочая ситуация

**Пройти курс** — попасть в ситуацию, принять решение, увидеть последствия, разобраться в принципе и попробовать действие в своей работе.

**Разобрать рабочую ситуацию** — выбрать проблему обычными словами, ответить на два уточнения и открыть подходящий пошаговый инструмент.

## Четыре этапа

### 1. Управлять собой и результатом

Как перестать только реагировать и начать управлять результатом?

- **Самоорганизация:** рабочий день, в который не помещаются все обещания. Распределите время и посмотрите, что вытесняется.
- **Регулярный менеджмент:** поручение с зависимостью. Выберите момент проверки, пока ещё можно изменить ход работ.

### 2. Управлять взаимодействием

Как получать результат через людей без постоянного ручного контроля?

- **Команда:** шкала самостоятельности, которая меняется вместе с задачей, опытом и риском.
- **Этика:** дерево решения с новой информацией о сроке, личной связи и справедливости очереди.
- **Коммуникация:** сообщение, которое можно собрать, сократить, переставить и отправить подходящим каналом.
- **Работа между подразделениями:** карта разных обязательств и выбора, который находится вне вашей роли.

### 3. Управлять системой

Почему люди могут всё делать правильно, а система всё равно работает плохо?

- **Документы и исполнение:** путь от подписи и версии до понимания, действия и принятого результата.
- **Процессы:** поток заявок, ожидание, возвраты и очередь, реагирующая на изменения условий.

### 4. Изменять и улучшать систему

Как изменить способ работы и убедиться, что он действительно помог?

- **Изменения:** разные группы обходят новый порядок по разным причинам. Подберите поддержку, которая попадёт в барьер.
- **Данные:** дашборд, на котором улучшение может скрывать потерю доступа или качества. Измените границы показателя.

После измерения эффекта вы возвращаетесь к следующему поручению и новому управленческому решению.

## Как проходит обучение

Сначала ситуация, затем человеческое объяснение и только после него название модели. Вместо кнопки «Понял» — короткое действие: выбрать факт, момент проверки, право решения или понятную формулировку.

Вопросы предлагают правдоподобные альтернативы. После решения разбираются его привлекательность и дальнейшие последствия. Варианты перемешиваются, а место остановки сохраняется.

## Одна история вместо десяти независимых вопросов

В управленческой симуляции вы ведёте общий административный сервис. Ручной контроль может улучшить первые сроки, но создать очередь у руководителя. Делегирование может ускорить ответы и одновременно открыть новый риск. Эти последствия меняют следующую ситуацию.

В конце — разбор решений в вашей истории: что помогло увидеть систему, где контроль оказался слишком ранним, как учитывались полномочия и границы данных. Это не психологическая диагностика.

## Одно действие в своей работе

Запишите, что попробуете изменить, где и когда проверите результат. Позже можно отметить: **помогло / частично помогло / не помогло** — и объяснить почему.

[Мои действия](experiments.html) — компактный список по датам. Прежние заметки и подробный дневник также доступны.

## Что остаётся под рукой

- Десять содержательных тем, 30 практических техник и рабочие шаблоны.
- Навигатор двенадцати повседневных проблем.
- Пять десятков вопросов для разбора решений и короткие действия внутри объяснений.
- [Адизес](adizes.html): PAEI, CAPI, жизненный цикл — как дополнительный взгляд, а не обязательная вставка в каждом объяснении.
- [Модели и литература](sources.html), избранное, отдельные страницы инструментов.
- [Настройки и копия данных](settings.html): профили, перенос и сохранённые записи.

Все примеры обезличены. Курс помогает запомнить ситуацию и логику решения, а рабочая среда — вернуться к ним, когда это нужно.

## Локальный запуск и проверки

Нужен **Node.js 24 или новее**. Из папки проекта:

```sh
npm ci
npm start
```

Откроется `http://127.0.0.1:4173`. Для native ES modules скачанную папку запускайте через локальный сервер. `npm run serve` запускает его без открытия браузера; другой порт: `npm run serve -- --port 4174`.

```sh
npm test
npm run lint:content
npx playwright install chromium
npm run test:browser
npm run build
```

Сборка создаёт `site/` с публичными страницами и вложенными модулями. GitHub Pages публикуется только после успешных CI-проверок. Расширенный редакторский отчёт: `npm run lint:content -- --report`.

При редактуре сохраняйте ID темы/техники/вопроса и канонический индекс старого ответа. У каждого варианта должны быть отдельные объяснения привлекательности и последствий. Новая причинная механика требует проверки изменения результата при изменении условий. Перед публикацией запускайте четыре проверки выше.

Архитектурная основа v3 сохраняется: страницы и общие сервисы используют модули, учебный renderer получает topic schema через compatibility adapter. Следующий приоритет — проверка игрового опыта, поэтому полный перенос прежних topics и массовая редактура объяснений отложены.

Игра изолирована в `assets/game/`, состояние — `course.projectGame`, revision 1; её архив — `course.projectGameArchive`. Старые simulation decisions не интерпретируются новым движком. Seed фиксирует базовые внешние события, а причинные последствия зависят от решений. Тесты движка: `node --test tests/game.test.cjs`; браузерный проход: `npm run test:browser -- tests/browser/game.spec.cjs`.
